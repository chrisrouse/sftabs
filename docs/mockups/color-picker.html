Org color picker — three shapes

All three are plain DOM, so they behave identically in Chrome and Firefox — which is the whole point, since <input type="color"> had to go because Firefox hands it to the OS dialog and the popup closes with it. Each is shown at the tray's real 380px against the real tokens. They are live — drag them.

Presets are dropped in all three, as chosen. Restoring shipped colors is still possible: the reset button already in the section header puts every environment back at once.

A · Sliders only

Three native range inputs. Reaches every color, and every accessibility affordance — arrow keys, Home/End, screen-reader announcement of the value — comes free from the platform rather than being re-implemented.

B · Square + hue strip

What most people mean by a color picker. Point at the color you want. Keyboard support has to be written by hand — the square is focusable and takes arrow keys here, with shift for coarse steps — because nothing native does this.

~130 lines, plus pointer capture, an ARIA story for the square, and a keyboard model invented here rather than inherited. The one shape people already know how to use.

C · Square and sliders

The square to choose by eye, the sliders to nudge one channel exactly — and as the keyboard path, which means the square's own key handling stops being load-bearing. They drive each other.

Note on B and C: the square is HSV, the sliders are HSL. That is the usual pairing and it is why dragging the square moves the Light slider in ways that can look surprising — the two describe the same color with different axes. Worth knowing before choosing C.
