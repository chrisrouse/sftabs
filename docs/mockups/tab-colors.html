Tab colour

Notes

A curated palette, not a colour wheel. Every swatch is an SLDS expressive-palette pair — the 40 for the accent, the 90 for any wash — so each one already has a dark-mode counterpart and known contrast. A free picker lets someone choose #ffff00, which is unreadable in light mode, invisible in dark, and ours to apologise for. Eleven hues is more than anyone will use.

Colour is optional and additive. tab.color would be a new optional field on TAB_STRUCTURE. Absent means today's behaviour exactly, so nothing changes for existing users and nothing changes for anyone who never opens the picker.

The treatment is a setting, not a decision. One preference — tabColorStyle — choosing none / dot / underline / tint / fill. You get the restrained version, someone migrating from the competitor gets what they are used to, and we do not have to be right about which is better.

Dark mode comes free, but only via the palette. Each pair is a light-dark(), so a tab coloured "teal" resolves to #056764 on white and #06a59a on dark. That is only possible because the value stored is a palette name, not a hex string. Storing hex would strand every coloured tab in one theme.

Fill has a real cost, which is why it is not the default. It overrides Salesforce's active-tab indicator, so the active tab stops being obvious — note how the mockup has to fake one with a dark bar. It also fights the org's own theme colour. Worth offering; not worth defaulting to.
