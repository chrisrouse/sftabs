Auto tab grouping

Yes — both browsers support it, with the same API and the same nine colors. Chrome has had chrome.tabGroups for years; Firefox shipped browser.tabGroups in 139, and we already require 142. Verified against both sets of docs in August 2026.

The thing to decide first, because everything else is detail. Grouping moves your tabs. The spec is explicit: “All tabs in a tab group must be adjacent, and tabs are moved if needed.” So switching this on rearranges the tab strip, and keeps rearranging it every time you open a Salesforce tab. That is the feature working correctly, not a bug — but it is a big change to something people arrange deliberately.

Note what happened to the Jira tab: it was second, and it is now last. Nothing moved it on purpose — it was simply in the way of two acme tabs becoming adjacent.

And the two sandboxes are still both green. Group colors are the same nine names in both browsers, so the per-org overrides you just set cannot come through — acme--dev1 and acme--uat are both “green” no matter what hex you picked. The group name carries the distinction; the color cannot.

No hex, in either browser. Mapping our environment defaults to the nearest of the nine, measured as CIELAB distance:

EnvironmentOur colorGroup color
production #c5221f → red
sandbox #1e8e3e → green exact
developer #1a73e8 → blue exact
scratch #7526e3 → purple
demo #b06000 → orange
patch #5c5c5c → grey
playground #0d9dda → cyan

Sandbox and Developer land exactly on the browser's own green and blue. Production, Scratch and Patch are close. Demo and Playground are not — a dark amber becomes a bright orange, and a mid cyan becomes a dark teal. All seven still map to distinct group colors, so nothing collides; they just stop being the colors you chose.

What it would cost to build

PieceNotes
Group on navigation Listen for a tab becoming a Salesforce URL, find or create that org's group in that window, tabs.group(). Ungroup when it navigates away.
One group per window Groups cannot span windows. Two windows on the same org means two groups with the same name — matching how profiles already resolve per page.
Respect manual edits If you rename or recolor a group by hand, we have to remember it and stop overwriting — otherwise the next tab you open reverts it. This is the piece that looks small and is not.
Naming The profile name where one covers the org, else the org identifier. Both already resolved.
One thing we must get right regardless. tabGroups has to go in optional_permissions, requested when the feature is switched on — not in permissions. Adding a required permission to an update disables the extension for every existing user until they re-approve it. Optional permissions are exempt.
